# Текущий статус проекта EvidenceXAI

Дата актуализации: `2026-05-29`

## 1. Назначение документа

Этот документ фиксирует фактическое состояние проекта на текущем локальном стенде и отделяет:

- что уже опубликовано в GitHub как код и документация;
- что находится только в локальной рабочей базе PostgreSQL;
- какой AI/OCR runtime реально включён сейчас;
- какие сценарии уже проверены на реальном кейсе.

## 2. Короткая сводка

Текущий продуктовый статус:

- `EvidenceXAI / EX.AI` — актуальное имя продукта и UI-бренд;
- `MVP 1` завершён как базовое функциональное ядро;
- активный инженерный горизонт — `MVP 2`, но часть прикладного трека государственной экспертизы уже реализована;
- iOS, внешние интеграции, ЭП и production hardening остаются вне текущего завершённого контура.

Текущий основной web-контур:

- организации;
- документы и дерево папок;
- обработка документов через Celery;
- отчёты;
- требования;
- матрица;
- риски;
- XAI-объяснения;
- экспорт `DOCX`, `XLSX`, `HTML`, `ZIP`.

Из UI сознательно убраны отдельные вкладки `Аудит`, `Уведомления` и `Редактор отчёта`. Audit/notification logic частично остаётся в backend как системный контур, но не является отдельной пользовательской вкладкой текущего интерфейса.

## 3. Фактический runtime сейчас

Текущий Docker Compose и launcher по умолчанию должны запускать локальный AI-режим:

```text
XAI_APP_AI_RUNTIME_PROFILE=baseline
XAI_APP_EMBEDDING_PROVIDER=ollama
XAI_APP_LLM_PROVIDER=ollama
XAI_APP_OCR_PROVIDER=tesseract
XAI_APP_OLLAMA_EMBEDDING_MODEL=all-minilm
XAI_APP_OLLAMA_LLM_MODEL=gemma3:270m
```

Это означает:

- `Ollama` должна быть запущена на локальном сервере или host machine;
- генеративная LLM используется через локальную модель `gemma3:270m`;
- neural embeddings используются через локальную модель `all-minilm`;
- OCR выполняется локально через `Tesseract`;
- visual signature/seal и visual quality сейчас работают как локальные baseline-эвристики;
- документы не отправляются во внешние OCR/LLM API.

В коде сохранён аварийный fallback, чтобы приложение не падало при недоступности Ollama. Но целевой режим проекта — не fallback, а локальные нейромодели и LLM.

Поддерживается profile-aware AI runtime:

- `baseline`;
- `quality`;
- `quality_plus`.

Для штатного запуска нужно использовать `bash infra/start_full_stack.sh`. Скрипт проверяет Docker, проверяет host Ollama, скачивает/проверяет модели и запускает backend/worker/frontend с provider-ами `ollama`.

Это важно: после клонирования репозитория на другой ПК приложение запустится, но база будет новой. Организации и реальные документы нужно импортировать или загрузить заново.

## 6. Основные выводы по реальному кейсу

Что работает:

- загрузка и хранение папочного дерева;
- обработка большого пакета документов;
- поддержка `PDF`, `DOCX`, `DOC`, `XLSX`, `XML`, `ZIP`, `SIG`, `P7S`, `GGE`, `JPG`;
- OCR baseline;
- state expertise workflow;
- XAI по findings;
- export `DOCX`, `XLSX`, `HTML`, `ZIP`.

Что требует дальнейшего усиления:

- `filename -> content` даёт много false-positive на хаотичных реальных названиях файлов;
- старые `.doc` требуют более сильного converter/parser;
- `.gge` пока сохраняется как evidence/metadata, но не разбирается семантически;
- OCR для многостраничных сканов ограничен demo-limit;
- список документов в API не должен по умолчанию возвращать полный `extracted_text` для больших пакетов.

1. Открыть `http://localhost:5173/login`.
2. Войти:
   - `admin@example.com`;
   - `ChangeMe123!`.
3. Перейти в `Организации`.
4. Выбрать `Водоканалпроект`.
5. Перейти в `Отчеты`.
6. Открыть отчёт `ПП 145 — Водоканалпроект — 1. ИРД — 2026-05-28 22:47`.
7. Смотреть интерактивный workflow, findings, XAI и export-действия.

Если список организаций пустой:

- убедиться, что открыт именно текущий локальный backend на `http://localhost:8000`;
- очистить frontend-сессию и войти заново;
- помнить, что на другом ПК локальная база будет пустой, пока данные не импортированы или не загружены заново.

## 8. Как правильно описывать состояние проекта

Корректная формулировка:

> EvidenceXAI — это локально разворачиваемая web-first платформа объяснимой подготовки отчётности. Базовый MVP завершён, а текущий код уже содержит расширенный прикладной трек государственной экспертизы с проверками ПП 145/ПП 87, workflow findings, XAI и экспортом. Штатный режим проекта использует локальные нейромодели через Ollama: `all-minilm` для embeddings и `gemma3:270m` для LLM, плюс локальный Tesseract OCR, rule-based decision layer, baseline vision/quality эвристики и обязательный XAI-слой по выводам.
