# Локальные границы runtime EvidenceXAI

Дата фиксации: `2026-05-28`

## 1. Основное правило

`EvidenceXAI` проектируется как локальный серверный контур:

- документы не отправляются во внешние OCR-сервисы;
- документы не отправляются во внешние LLM API;
- OCR, embeddings, LLM, XAI, benchmark и экспорт выполняются внутри локального стенда;
- Docker Compose является основным способом запуска демо и разработки.

## 2. Что означает “локальная модель”

Локальная модель — это модель или библиотека, которая установлена на сервере EvidenceXAI и вызывается backend/worker-процессами.

Примеры допустимого локального runtime:

- `Tesseract` внутри backend container;
- `Ollama` на том же сервере или host machine;
- локальная embedding-модель через `Ollama`;
- локальная LLM через `Ollama`;
- layout-baseline detector в Python-коде backend;
- в будущем: локальный PaddleOCR/ONNX/PyTorch provider, если он будет установлен в контейнер или на тот же сервер.

Недопустимый для текущей архитектурной границы вариант:

- отправлять пользовательские документы во внешний OCR API;
- отправлять пользовательские документы во внешний LLM API;
- строить обязательную проверку через внешний SaaS.

## 3. Текущий OCR / vision contour

В текущей реализации:

- OCR provider: локальный `Tesseract`;
- image-only `PDF` рендерится локально и передаётся в локальный OCR provider;
- визуальная проверка подписи/печати работает через `layout-baseline-v1`;
- `layout-baseline-v1` анализирует изображение или первую страницу PDF локально;
- оценка визуального качества работает через `layout-quality-baseline-v1`;
- `layout-quality-baseline-v1` измеряет разрешение, контраст, резкость, dark/bright ratio и признаки blank-like страницы;
- орфография, терминология и OCR-noise проверяются локальным `local-terminology-rules-v1`;
- `local-terminology-rules-v1` использует встроенный словарь проектно-сметных терминов и не вызывает внешние grammar/spell API;
- `/api/system/ai-status` показывает `runtime_scope = local_server` и `sends_documents_to_external_services = false` для OCR и vision.

`PaddleOCR` может рассматриваться только как будущий локальный provider. Это не требование использовать внешний сервис.

## 4. Нормативная проверка rules pack

Фраза “валидация rules pack” означает не вызов внешнего юриста или внешней системы, а внутренний контроль качества нормативного набора правил:

- rules pack имеет версию;
- у правила есть нормативное основание;
- у правила есть дата актуализации;
- результат benchmark фиксируется в generated artifacts;
- пользователь видит disclaimer: автоматизированная проверка не заменяет государственную экспертизу.

Для дипломного MVP достаточно внутренней нормативной проверки по открытым нормативным источникам и сохранения XAI-основания по каждому выводу.

## 5. Что остается ограничением

Система может определить:

- наличие визуального признака подписи;
- наличие визуального признака печати;
- слабый OCR/text layer;
- расхождение названия файла и содержания;
- отсутствие ожидаемой группы документов;
- ссылку на нормативное основание.

Система не должна утверждать:

- юридическую подлинность рукописной подписи;
- юридическую действительность печати;
- окончательное решение органа государственной экспертизы.

Правильная пользовательская формулировка: `предварительная автоматизированная проверка пакета документов с XAI-объяснениями`.
